9CT.04 - Sub-routines

Notes: A sub-routine is a named block of steps that can be called when needed. It reduces repetition and makes algorithms easier to read and maintain.
Exam note: If a question asks why a sub-routine is used, mention readability, reusability, and easier testing/debugging.

Mini pseudocode

MAIN
  INPUT name
  CALL FormatGreeting(name)
  OUTPUT message
END MAIN

SUB-ROUTINE FormatGreeting(personName)
  message <- "Welcome " + personName
END SUB-ROUTINE

Visual flowchart: Call and return

Exercises

  1. Rewrite this repeated action using one sub-routine: "calculate total marks" appears three times in one algorithm.
  2. Name two benefits and one risk if a sub-routine is badly named.
  3. Where does control go after a sub-routine finishes?
Answer guide: create a sub-routine like CalculateTotalMarks, call it when needed; benefits include less duplication and easier maintenance; control returns to the line after the call.

9CT.05 - Binary Search

Notes: Binary search repeatedly checks the middle value and removes half the remaining values. It only works correctly on sorted data.
Exam note: In trace questions, always track low, high, and mid after each decision.

Short trace example

Flowchart

Quick compare

  • Linear search checks one-by-one and works on unsorted data.
  • Binary search halves the list each step, but only if sorted.
  • For large lists, binary search usually needs far fewer checks.

Exercises

  1. List one reason binary search can fail if the data is unsorted.
  2. For 32 sorted items, estimate the maximum checks binary search needs.
  3. Suggest one real-life dataset where binary search is suitable.
Answer guide: unsorted data breaks the left/right elimination logic; for 32 items about 5 checks; suitable examples include sorted student IDs or sorted word lists.

9CT.08 - Comparing Algorithms

Notes: Comparing algorithms means evaluating more than speed. You should consider correctness, readability, memory use, and suitability for the context.
Exam note: Strong answers justify a choice with evidence and context, not just "this one is faster".

How to justify a choice

  1. State the context (data size, sorted or not, time limit).
  2. Apply criteria (speed, simplicity, memory, maintainability).
  3. Conclude with evidence (estimated checks, constraints, trade-offs).

Exercises

  1. Compare linear search and binary search for an unsorted class register.
  2. Compare them again for a huge sorted exam database.
  3. Give one case where the simpler algorithm is a better classroom choice.
Answer guide: unsorted register favors linear search; huge sorted data favors binary search; simpler methods can be preferred for teaching clarity or tiny datasets.

9CT.09 - Combining Constructs

Notes: Real algorithms usually combine sequence, selection, iteration, and sometimes sub-routines. The skill is choosing where each construct belongs.
Exam note: When asked to improve an algorithm, explain which construct you changed and why it improves logic or efficiency.

Combined flowchart example: Library fine checker

Scenario: process each borrowed book, decide if overdue, and call a sub-routine to compute fine.

Construct map (quick reference)

  • Sequence: ordered steps run once.
  • Selection: branch based on a condition.
  • Iteration: repeat until a count or condition is met.
  • Sub-routine: reusable named block called from main flow.

Exercises

  1. Write a short algorithm that loops through 10 marks and uses selection to count passes.
  2. Add one sub-routine to your algorithm and explain what it does.
  3. State one testing advantage of splitting logic into constructs and sub-routines.
Answer guide: use a loop + IF for pass count; sub-routine example: ValidateMark or FormatReport; modular design supports isolated testing and easier debugging.
