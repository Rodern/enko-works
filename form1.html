✅ Accurate flowchart checklist

  • It must have a Start and a Stop.
  • All inputs and outputs should use a parallelogram.
  • All processes should use a rectangle.
  • A selection should use a diamond.
  • A decision should have two arrows out labelled yes/no or true/false.
  • All arrows should clearly show the direction of flow.

🔀 Flowchart foundations

Sequence, selection, and sub-routines

  • Sequence: steps happen in order, one after another.
  • Selection: the algorithm chooses a path based on a question.
  • Sub-routine: a named mini-algorithm used from the main algorithm.

Quick warm-up questions

  1. What shape is used for input and output?
  2. Why does a decision need a yes/no answer?
  3. When would a sub-routine be useful?
  4. How can you spot a repeated pattern in an algorithm?

7CT.01

Follow, understand, edit and correct algorithms that are presented as flowcharts

follow arrows spot errors input/output

Memorize

  • Read a flowchart from Start to Stop.
  • Follow the arrows in the correct order.
  • Each shape tells you what kind of step is happening.
  • If a result is wrong, one step in the chart may need correcting.

Understand

When following a flowchart, ask these questions:

  1. What is being input?
  2. What process or calculation is done?
  3. What is the output?
  4. Does the chart really match the task?
A common error is when the process box uses the wrong operation, such as subtracting when it should multiply.

Demonstrate

Worked example: This flowchart takes two inputs and finds the average.

Students should be able to explain each shape and say what the chart outputs.

Error spotting: if the process box showed first - second, the flowchart would not be finding an average correctly.

Practice

  • Describe in words what the average flowchart does.
  • Explain how to fix a chart that subtracts when it should multiply.
  • Find a missing input in a flowchart that outputs a favourite colour but never asks for it.
  • Identify the purpose of the rectangle symbol.
7CT.02

Know how to create algorithms using flowchart symbols

symbols draw accurately structure

Memorize

  • Start and Stop must be clear.
  • Use the correct symbol for each task.
  • Every box must connect to another box using arrows.
  • A decision should have only two clear answers at this level.

Understand

To create a good flowchart, first read the task carefully. Then break it into simple steps:

  1. What is the input?
  2. What process happens?
  3. Is there a decision?
  4. What should be output?

Demonstrate

Task: Display a welcome message, ask for age, and output whether the user gets a discount if they are under 18.

Flowchart order: Start → Output “Welcome” → Input age → Decision age < 18? → Yes: Output “Discount” → Stop / No: Output “No discount” → Stop.

Notice that this task uses both sequence and selection.

Practice

  • Draw a flowchart that asks for a user’s name and outputs a welcome message.
  • Turn this description into a flowchart: ask the user if they like computer games; if yes, ask for their favourite game; if no, suggest an introductory game.
  • Check your work using the flowchart checklist above.
7CT.04

Understand and use selection statements, limited to IF, THEN, ELSE, presented as flowcharts

IF THEN ELSE decision

Memorize

  • IF asks a question.
  • THEN is the action when the answer is true / yes.
  • ELSE is the action when the answer is false / no.
  • Selection is shown using a diamond in a flowchart.

Understand

A selection flowchart gives a choice. Only one branch is followed at a time.

At this level, the question in the diamond must be something that can be answered with yes/no, true/false.

Demonstrate

This selection flowchart uses a question and two different outputs.

Practice

  • Label the two branches of a decision diamond: and .
  • Write a real-life IF, THEN, ELSE statement of your own.
  • Draw a flowchart for: If your favourite colour is red, stand up, otherwise sit down.

The two branches should be labelled Yes / No or True / False.

7CT.05

Predict the outcome of flowcharts that use selection

predict output test data follow branches

Memorize

  • Use the input values given in the question.
  • Check the decision carefully.
  • Follow only the correct branch.
  • Write the final output exactly.

Understand

If a flowchart compares two numbers, the input values decide which path is followed. Students should be able to explain why the output is correct.

7CT.09

Select and use appropriate comparison operators in flowcharts

< > == !=

Memorize

  • == means equal to.
  • != means not equal to.
  • > and < compare bigger and smaller values.
  • >= and <= include equality as well.

Understand

Choosing the correct operator matters. If the wrong operator is used, the flowchart may follow the wrong branch and give the wrong output.

In algorithms, == is used to test equality. It is not the same as using a single equals sign in mathematics.

Demonstrate

Is 4 > 5 true or false?

False

Which operator makes this true: 19 __ 19?

== because both values are equal.

Practice

  • Fill in the best operator: age __ 12 to mean “age is 12 or older”.
  • Write one question using !=.
  • Explain the difference between < and <=.
7CT.08

Select and use appropriate constructs in algorithms written as flowcharts, limited to sequence and selection

sequence selection choose structure

Memorize

  • Use sequence when all steps happen in order.
  • Use selection when there is a choice or question.
  • Some tasks use both: first sequence, then selection.

Understand

Before drawing, decide what kind of structure the problem needs. This makes the flowchart clearer and more accurate.

TaskConstruct needed
Ask for name and print itSequence
Ask if age is under 18, then choose a messageSelection
Input two numbers, compare them, then output resultSequence + Selection

Demonstrate

Task: Ask for a user’s age. If the age is below 18, output “discount”, otherwise output “standard price”.

This needs sequence for the input, then selection for the decision and two possible outputs.

Practice

  • Decide whether each new problem needs sequence, selection, or both.
  • Draw a flowchart for a task that uses sequence only.
  • Draw one that uses both sequence and selection.
7CT.07

Follow, understand, edit and correct algorithms that use sub-routines

sub-routine call reuse

Memorize

  • A sub-routine is a separate named algorithm.
  • It can be called from the main algorithm.
  • It helps when the same steps might be needed more than once.
  • The same name should be used when defining and calling it.

Understand

Sub-routines make algorithms more organised. Instead of writing the same steps many times, the main algorithm can call a named section when needed.

The main flowchart calls the sub-routines Greet and Farewell.

Demonstrate

Why are sub-routines helpful?

They help when the same steps are repeated. You can write them once and call them from the main algorithm whenever needed.

If a flowchart calls the wrong sub-routine or uses the wrong name, what should happen?

The name or the call should be corrected so the right sub-routine runs at the right point.

Practice

  • Trace the output of a flowchart that calls two sub-routines.
  • Correct a flowchart where the wrong sub-routine is called.
  • Explain the purpose of the sub-routine symbol.
  • Describe one task where a sub-routine would be useful.
7CT.06

Explain the importance of pattern recognition when designing solutions to tasks

patterns repetition design

Memorize

  • A pattern is something that repeats.
  • Pattern recognition helps us spot repeated steps.
  • If steps repeat, they may be turned into a sub-routine.
  • This makes the solution clearer and easier to improve.

Understand

Look at this repeated structure:

  • Output “Enter the first number”
  • Take a number as input, add 20, and output it
  • Output “Enter the second number”
  • Take a number as input, add 20, and output it

The repeating part is input number → add 20 → output. That repeated part could become a sub-routine.

Demonstrate

How can pattern recognition help a programmer?

It helps the programmer notice repeated steps and organise them better, often by using a sub-routine instead of rewriting the same work again and again.

Practice

  • Find the repeated pattern in a task of your own.
  • Explain how that repeated pattern could become a sub-routine.
  • Write one reason why pattern recognition saves time or improves design.
